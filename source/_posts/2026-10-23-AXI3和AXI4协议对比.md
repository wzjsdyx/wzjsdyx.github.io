# AXI3 vs AXI4：信号接口差异







# AXI3 vs AXI4：协议行为差异对比

> 主要参考：IHI0022C_amba_axi_v2_0_protocol_spec.pdf
>
> Arm《AMBA AXI Protocol Specification》，ARM IHI 0022C，Chapter 13（AXI4）。该章节专门说明AXI4相对于AXI3的变化

## 一、核心协议行为差异

| Feature                   | AXI3                                            | AXI4                                                         | 官方章节 |
| ------------------------- | ----------------------------------------------- | ------------------------------------------------------------ | -------- |
| Burst Length              | 最多16 Beat                                     | INCR最多256 Beat，FIXED/WRAP仍最多16 Beat                    | §13.1    |
| Burst拆分                 | 最大16 Beat，无需支持更长Burst                  | 超过16 Beat的Burst允许拆分，即使是Non-modifiable事务，但有额外约束 | §13.1    |
| Write Interleaving        | 允许不同ID写事务的数据交织，取决于Slave支持能力 | 完全禁止Write Interleaving                                   | §13.16   |
| Write Data Ordering       | 支持交织时，不同事务写数据可交错传输            | W通道数据必须按AW事务顺序传输，同一Burst的数据Beat连续排列（允许等待周期） | §13.16   |
| Write Response Dependency | 最后一个W Beat接收完成后才允许产生BVALID        | 必须同时完成AW握手和最后一个W Beat握手，才能产生BVALID       | §13.4    |
| Locked Transaction        | 支持Locked和Exclusive访问                       | 取消Locked，只保留Exclusive                                  | §13.15   |
| QoS                       | 无标准QoS标识机制                               | 引入事务QoS标识，供系统级仲裁使用；不强制具体算法            | §13.2    |
| Region                    | 无标准Region标识机制                            | 一个物理Slave接口可以对应最多16个逻辑Region                  | §13.3    |

上述差异均来自Arm官方规范。

其中有三个容易混淆的地方：

1. AXI4取消Write Interleaving，不是取消Read Interleaving。 AXI4仍允许不同ID的读数据交织。
2. AXI4取消Write Interleaving，不是取消Outstanding和Out-of-Order。 这些能力仍然保留。
3. AXI4允许W数据先于AW地址到达。 AW与W通道的握手仍相互独立，只是BVALID的产生条件更加严格。

例如两笔写事务A、B：

```
AXI3：可以
AW顺序： A       B
W顺序：  A1 B1 A2 B2 A3 B3

AXI4：必须保持写数据事务顺序
AW顺序： A       B
W顺序：  A1 A2 A3 B1 B2 B3
```

这属于协议明确规定的行为，不是推测。

## 二、Memory Attribute与Ordering行为差异

这一部分对NIC-400尤其重要，因为会影响Interconnect中的事务拆分、合并、Buffering和顺序控制。

| Feature                                           | AXI3                                                         | AXI4                                                         | 官方章节      |
| ------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ | ------------- |
| <font color=red>Transaction Modification</font>   | `AxCACHE[1]`定义为Cacheable                                  | 重新定义为Modifiable，明确允许或禁止事务参数修改             | §13.5         |
| <font color=red>Non-modifiable Transaction</font> | 未采用AXI4的明确约束体系                                     | 原则上禁止拆分、合并、修改事务参数；长Burst拆分等有例外      | §13.5         |
| <font color=red>Cache Allocate</font>             | Read Allocate、Write Allocate主要反映相应访问导致的Cache分配可能性 | 扩展语义，考虑其他Master等事务导致的Cache分配                | §13.7         |
| <font color=red>Memory Type</font>                | 使用AXI3 Cache属性定义                                       | 明确Device、Normal Non-cacheable、Write Through、Write Back等类型及行为 | §13.8         |
| <font color=red>Non-modifiable Ordering</font>    | 未明确强制规定                                               | 同ID、同方向、访问同一Slave的Non-modifiable事务必须保持顺序，即使地址不同 | §13.6         |
| <font color=red>Device Ordering</font>            | 未明确要求同ID访问同一Device时必须按序到达                   | 增加明确的排序保证，与具体访问地址无关                       | §13.12～13.13 |
| <font color=red>Normal Memory Ordering</font>     | 已有基于ID的排序机制                                         | 明确相同或重叠地址的排序、可见性要求                         | §13.13        |
| <font color=red>Transaction Buffering</font>      | 有Bufferable属性                                             | 进一步明确不同Memory Type的响应位置、最终可见性及Buffer排空要求 | §13.10        |
| Mismatched Attributes                             | 缺少AXI4所述的完整约束说明                                   | 明确多个Master使用不同Memory Attribute访问同一区域时的兼容条件 | §13.9         |
| Single-copy Atomicity                             | 已支持原子访问相关机制                                       | 进一步明确Single-copy Atomicity Size及Atomic Group要求       | §13.13.4      |

以上属于官方规范明确增加、更新或澄清的协议要求；其中不代表每一项都是AXI4才首次具备的硬件能力。例如Buffering和ID排序在AXI3中已经存在

重点解释其中两个容易混淆的机制：

1. Transaction Modification

AXI4明确区分：

- `AxCACHE[1]=0`：Non-modifiable，通常禁止Interconnect修改Burst参数或合并、拆分事务。
- `AxCACHE[1]=1`：Modifiable，允许符合约束的Burst拆分、合并、宽度调整等操作。

例外是长度超过16 Beat的Non-modifiable Burst，仍允许按规范拆分。

2. Ordering

AXI4明确区分Device和Normal Memory的排序要求：

- Device：同ID、同方向、同Slave的事务需要保持顺序。
- Normal：同ID、同方向、访问相同或重叠地址的事务需要保持顺序。
- 不同ID：响应允许乱序，但仍须满足地址重叠时的可见性等约束。
- 读写跨方向：不自动保证先后顺序，若需要排序，Master应等待前一事务响应后再发起后一事务。

这里关于Device排序的加强，是Arm规范§13.12明确指出的AXI3与AXI4区别





## 三、扩展能力与兼容性差异

| Feature                                   | AXI3               | AXI4                                                         | 官方章节      |
| ----------------------------------------- | ------------------ | ------------------------------------------------------------ | ------------- |
| User Sideband                             | 无标准化USER信号组 | 定义5个通道的可选USER信号，但不规定其业务含义                | §13.14        |
| 接口裁剪                                  | 已存在简化实现     | 更系统地规定可选信号、默认值和接口互操作条件                 | §13.17        |
| <font color=blue>Legacy Locked转换</font> | 允许Locked事务     | AXI3 Locked转换到AXI4时映射为Normal事务，可能失去原锁定语义  | §13.15        |
| <font color=blue>AXI3/AXI4互操作</font>   | 支持≤16 Beat       | 长Burst连接AXI3 Slave需要转换Wrapper；还需处理写数据顺序等兼容性 | §13.1、§13.16 |



## 四、哪些核心机制没有改变？

这一部分建议在知识库中单独保留，避免把AXI3已有的机制误认为AXI4新增。

| Feature                                        | AXI3和AXI4                   |
| ---------------------------------------------- | ---------------------------- |
| 五通道结构                                     | 都是AW、W、B、AR、R          |
| Handshake                                      | 都采用VALID/READY            |
| Outstanding                                    | 都支持多笔未完成事务         |
| Out-of-Order                                   | 都允许不同ID事务乱序完成     |
| Read Interleaving                              | 都允许不同ID读事务的数据交织 |
| Same-ID Response Ordering                      | 同ID、同方向响应必须保持顺序 |
| Exclusive Access                               | 都支持                       |
| Narrow / Unaligned Transfer                    | 都支持                       |
| 4KB Boundary                                   | Burst均不允许跨越4KB边界     |
| <font color=red>Early Burst Termination</font> | 都不支持提前终止Burst        |

这些属于两代协议的共同基础机制
