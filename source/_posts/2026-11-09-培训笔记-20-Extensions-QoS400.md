> Advanced Quality of Service (QoS-400) is considered an add-on to the NIC-400 and included within the NIC-450. By enabling the additional options provided in the NIC-450 bundle, you can add functionality to the NIC-400. The problem shown here is that some resources can hog bandwidth and memory. 
>
> Here we see a stall caused by the GPU which has high bandwidth and is flooding the system with requests causing CPU performance degradation and the LCD real-time requirements missed, causing display corruption. 
>
> QoS-400 adds some innovative regulators to the NIC-400 that can be used to more carefully fine-tune the amount of bandwidth given to each master and balance traffic when trying to access the same locations. The outstanding transaction (OT) regulator allows you to reduce the number of outstanding transactions passing through a particular point in the system. This regulator is used when you have some components (for example, a GPU) that might request far more bandwidth than it needs to use immediately. The regulator, in such a case, can reduce the outstanding transaction value. The transaction issuing regulator is similar to the OT regulator, except that it is a bit cleverer, so it does not set a fixed number of OTs. Instead, it sets an average rate (how much BW we expect that master to request or a “limit”), a peak rate (the master can temporarily exceed the average rate up until the peak rate), and a burstiness value (the amount of time it can spend at the peak rate). Instead of setting a fixed number of outstanding transactions like an outstanding transaction regulator, the transaction issuing rate regulation allows you to set an average rate at a peak. The average rate value is how much you expect this master to request or set a limit on how much you expect this master to be able to request. However, with transaction issuing rate regulation, the master can temporarily exceed the average rate up until the peak. This ability gives you more flexibility and allows the master to use the spare bandwidth available in the system. These first two are known as “hard regulators” as they limit the number of transactions issued through a point in the system. The address request/latency regulation can adjust the QoS value of transactions that pass through this point in the system based on the programmed target latency. Suppose the regulator detects that transactions are taking longer than the programmed target latency. In that case, the QoS value will go up (otherwise, if the transactions complete faster, then the QoS value will go down). The main idea is that over time all these different regulators will balance, such that you can hit your required latency figures through each of these different points.

### 1. Advanced QoS（高级服务质量）简介

Advanced Quality of Service（QoS-400）被认为是 NIC-400 的一个附加组件，并且已经集成在 NIC-450 中。

通过启用 NIC-450 软件包中提供的额外选项，可以为 NIC-400 增加更多功能。

这里展示的问题是：某些组件可能会大量占用系统带宽和内存资源。

例如，GPU 具有很高的带宽需求，持续向系统发送大量访问请求，导致：

- CPU 的访问请求被阻塞，性能下降。
- LCD 无法满足实时性要求。
- 最终造成显示数据异常（Display Corruption）。

QoS-400 为 NIC-400 增加了一些先进的流量调节器（Regulators），可以更精细地控制分配给各个 Master 的带宽，并在多个 Master 访问相同资源时平衡系统流量。

### 2. Outstanding Transaction Regulator（OT 调节器）

Outstanding Transaction Regulator 允许限制通过系统某个特定位置的 Outstanding Transactions（未完成事务）的数量。

当某些组件（例如 GPU）请求的带宽远大于其当前实际需要使用的带宽时，可以使用这种调节器。

在这种情况下，OT Regulator 可以减少允许通过的 Outstanding Transactions 数量，从而限制该组件对系统资源的占用。

### 3. Transaction Issuing Regulator（事务发送速率调节器）

Transaction Issuing Regulator 与 OT Regulator 类似，但是更加智能。

它并不是简单地设置固定的 Outstanding Transaction 数量，而是配置三个参数：

- Average Rate（平均速率）：Master 预期的平均请求速率，或者允许的平均速率上限。
- Peak Rate（峰值速率）：Master 可以暂时超过平均速率，但不能超过设置的峰值速率。
- Burstiness（突发程度）：Master 可以以峰值速率持续发送请求的程度。

与 OT Regulator 限制固定 Outstanding 数量不同，Transaction Issuing Regulator 可以同时配置平均速率和峰值速率。

Master 可以在短时间内超过平均速率，达到峰值速率。

这种机制提供了更高的灵活性，使 Master 能够充分利用系统中暂时空闲的带宽。

前面介绍的两种调节器称为 Hard Regulators（硬限制调节器），因为它们会直接限制通过系统某个位置的事务数量或发送速率。

### 4. Address Request / Latency Regulation（地址请求/延迟调节器）

Address Request / Latency Regulator 可以根据预先配置的目标延迟（Target Latency），动态调整经过该调节器的事务的 QoS 值。

具体来说：

- 如果调节器检测到事务实际延迟超过配置的 Target Latency，就会提高对应事务的 QoS 值。
- 如果事务完成得比 Target Latency 更快，就会降低对应事务的 QoS 值。

核心思想是：通过持续动态调整不同事务的 QoS 优先级，让系统内各个 Master 的访问延迟逐渐达到平衡，最终尽可能满足各自的延迟要求



# 原理解释

QoS-400 的核心目标是：

防止高带宽 Master 长期占用系统资源，确保 CPU 性能和实时外设的访问延迟。

### 1. 为什么需要 QoS-400？

假设 SoC 中有三个 AXI Master，共同访问 DDR：

![image-20261109175855545](D:\blog\wzjsdyx.github.io\source\_posts\2026-11-09-培训笔记-20-Extensions-QoS400\image-20261109175855545.png)



三个 Master 的需求不同：

| Master | 特点                 | 主要需求       |
| ------ | -------------------- | -------------- |
| CPU    | 带宽较低，访问不规则 | 低延迟         |
| GPU    | 持续发起大量访问     | 高吞吐量       |
| LCD    | 周期性读取显示数据   | 确定的访问延迟 |

如果 GPU 持续大量发送事务，即使 CPU、LCD 也能参与仲裁，仍然可能因为系统拥塞而出现严重延迟。

因此需要 QoS-400。

### 2. 三种 Regulator 的区别

以 GPU 为例。

① OT Regulator：限制并发事务数量

假设 GPU 最多可以发出 16 个 Outstanding Transactions。

配置 OT Limit = 4 后：

- 最多允许 4 个受控事务处于 Outstanding 状态。
- 当 Outstanding 达到 4 时，后续事务暂时不能继续发出。
- 等其中一个事务完成，才能继续发送新事务。

这相当于限制 GPU 同时占用系统资源的事务数量。

但需要注意：OT=4 不等于 GPU 只能使用 25% 的 DDR 带宽。 实际吞吐量还取决于事务大小、延迟等因素。

② Transaction Issuing Regulator：限制事务发送速率

假设配置如下（仅用于理解概念，并非实际寄存器参数）：

| 参数         | 示例值         |
| ------------ | -------------- |
| Average Rate | 100 个事务/μs  |
| Peak Rate    | 200 个事务/μs  |
| Burstiness   | 允许短时间突发 |

此时：

- 正常情况下，GPU 的长期平均发送速率受到限制。
- 系统允许时，可以短时间提升至峰值速率。
- 不能无限期保持峰值，否则会破坏平均速率约束。

这比固定 Outstanding 数量更加灵活，适合有突发流量需求的 Master。

③ Latency Regulator：动态调整事务优先级

假设 LCD 要求访问延迟尽量控制在 100ns 内。

配置 Target Latency = 100ns：

| 实际延迟 | 调节方式                 |
| -------- | ------------------------ |
| 150ns    | 提高 QoS 优先级          |
| 100ns    | 目标附近，按控制算法调整 |
| 50ns     | 降低 QoS 优先级          |

注意，这里的 100ns 是示例值。

Latency Regulator 不直接限制事务数量，而是通过调整 QoS，影响 NIC-400 的后续仲裁结果。

因此它属于动态优先级调节机制，而不是 Hard Regulator。

### 3. 三种机制对比总结

| Regulator                     | 控制对象         | 主要作用                   |
| ----------------------------- | ---------------- | -------------------------- |
| OT Regulator                  | Outstanding 数量 | 限制同时在途事务           |
| Transaction Issuing Regulator | 事务发送速率     | 限制平均速率，允许短时突发 |
| Latency Regulator             | AXI QoS 优先级   | 根据延迟目标动态调整优先级 |

## 三、需要特别理解的两个问题

问题 1：为什么限制 OT 数量也能改善带宽分配？

因为 Master 能同时发出的事务越多，通常越容易保持下游资源繁忙。

限制 GPU 的 OT 数量，可以减少 GPU 对 DDR Controller 等共享资源的持续占用，使 CPU 和 LCD 有更多获取服务的机会。

但 OT 限制并不能严格保证某个 Master 获得固定带宽。

问题 2：Latency Regulator 能保证实时性吗？

不能保证。

Latency Regulator 只能通过提高 QoS 优先级，改善事务的仲裁机会。

如果 DDR 本身已经完全饱和，或者下游没有有效利用 QoS 信息，单纯提高优先级无法确保满足延迟指标。

因此，实际 SoC 设计中通常需要组合使用 Hard Regulator 和 Latency Regulator，同时控制系统拥塞程度和关键 Master 的服务优先级。

一句话总结：

QoS-400 通过三类调节器实现流量管理：

- OT Regulator：管并发数量。
- Transaction Issuing Regulator：管发送速率。
- Latency Regulator：管动态优先级。

三者配合，避免 GPU 等高带宽 Master 过度占用资源，同时尽可能保障 CPU 和 LCD 等 Master 的性能与实时性。
