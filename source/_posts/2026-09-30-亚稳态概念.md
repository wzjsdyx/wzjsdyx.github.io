> 亚稳态通常最终会恢复到稳定的 0 或 1，但是真正危险的地方是不知道什么时候恢复。
>
> 如果是多个bit进行同步，有可能会恢复成不同的状态，拼出一个根本不存在的数据。因此使用格雷码解决这种问题。
>
> 理论上：
>
> 亚稳态持续 100ps   → 概率较大
> 亚稳态持续 1ns     → 概率小很多
> 亚稳态持续 10ns    → 概率极低
> 亚稳态持续更久     → 仍然不是严格的 0





# **如果不做同步会出现什么问题？**

亚稳态会传播到后面的电路,(后级电路看到的数据不一致,也可能后级电路自身也进入亚稳态)

比如：

```
async_sig ─────► FF1 ─────► combinational logic ─────► FF2/FF3...
                  ↑
               直接采样
```

如果 `async_sig` 恰好在 FF1 的 setup/hold 窗口附近变化，FF1 可能亚稳：

```
FF1.Q = ??? → 最终恢复成 0/1
```

<font color=blue>问题在于恢复之前，后级逻辑已经看到这个不确定状态了。</font>

例如一个信号同时进入两个寄存器：

```
               ┌── FF_A
async ── FF ───┤
               └── FF_B
```

亚稳态期间，可能出现：

FF_A 认为是 1

FF_B 认为是 0

> 原因：
>
> 假设FF处于0/1的阈值中间，然后FF_A 和 FF_B 对这个进行采样，可能采样出不同结果。

于是本来应该一致的两个状态发生分叉，严重时可能导致：

- 状态机进入非法状态
- counter/控制信号误触发
- pulse 丢失或重复
- 不同逻辑模块看到不同值
- 极低概率、难复现的芯片现场 bug

<font color=blue>所以同步器的主要作用是：把容易亚稳的第一级 FF 隔离起来，不让它直接驱动功能逻辑。在第二级的,一般认为是确定的值。就可以传递给后级电路</font>









# **2级同步？多级同步原理？**

<font color=blue>亚稳态的“恢复”发生在触发器 FF 内部的存储节点上，不是 wire 自己在恢复</font>.

第一级DFF采样到异步信号，可能进入亚稳态；

第二级DFF采样的时候，第一级的DFF在经过一个Cycle之后，可能已经走出亚稳态，输出变成0/1;

<font color=blue>通常来说，从第二级输出之后，被认为是稳定的信号。</font>



多级同步的原理也是如此，

第三级采样的时候，第二级的DFF Q，在已经经过1T的恢复基础上，又经过了一个Cycle。

第四级采样的时候，第三级的DFF Q，在已经经过2T的恢复基础上，又经过了一个Cycle。

# **Q&A:为什么工程上，感觉是最终能够恢复到正确的值？**



>  假如寄存器的D端，从0->1， D 跳变以后长期保持在 1，触发器内部在采样窗口关闭过程中，新的 `1` 往往会对内部节点形成一定的“偏置”，所以最终落到新值的概率可能更高。但是并不一定保证恢复为1。



<font color=blue>为什么工程中感觉问题不大或者感觉不出来？因为对于单 bit CDC 同步器来说，这两种结果通常都允许。</font>

例如对于两级同步器，第一级DFF D端，从0->1；

如果 FF1 最后恢复成 `1`：

```
第 N 拍：FF1 = 1
第 N+1 拍：FF2 = 1
```

如果 FF1 最后恢复成 `0`：

```
第 N 拍：FF1 = 0
第 N+1 拍：FF1 = 1
第 N+2 拍：FF2 = 1
```

结果只是：这个跳变到底被认为发生在第 N 拍还是第 N+1 拍，对电路其实没啥影响

<font color=blue>所以同步器并不要求 FF1 一定恢复成“正确的新值”，它真正要求的是：FF1 在 FF2 下一次采样前恢复成一个稳定的 0 或 1。这也是理解 CDC 最关键的一点。</font>
